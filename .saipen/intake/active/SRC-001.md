[P0] [CORE-001] delete_duplicates_gui.py:DuplicateEngine.scan / verify_record / plan_deletion — survivor invariant counts symbolic-link aliases as independent surviving copies

- FileRecord carries only path/size/fingerprint (lines 111-117), so the model cannot distinguish an independent copy from a symlink alias to another group member.
- plan_deletion() considers any unselected member whose verify_record() succeeds to be a kept copy (lines 282-290).

- Deterministic real-filesystem reproduction:
  target `a.bin` contained DUPLICATE-CONTENT and `z-link.bin` was a symlink to `a.bin`.

  After deleting the approved target: target_exists=False, link_lexists=True, link_resolves=False.
- Targeted audit test `test_symlink_is_not_accepted_as_surviving_copy_of_deleted_target` FAILED because refused_groups was [].
- README.md:20 and README.ru.md:17 promise that at least one verified copy always remains.
DEFECT:
The safety model is path-based rather than storage-object/alias-aware. A symlink to a selected real file passes verification as the supposedly retained copy. VERIFY:
